版本：2.0（前端 MVP）
状态：本地演示模式已实现
产品代号：BenchFlow（暂定，不代表商标或域名）

---

## 1. 产品定位

BenchFlow 是面向硬件研发团队的测试管理与协作平台。它解决的核心问题不是“记录一次测试”，而是让**测试结论可追溯**：

- 这次测试跑的是哪个产品的哪个硬件 / 固件版本？
- 用了哪台设备，设备是否在校准有效期内？
- 测试条件、测量值、判定阈值分别是什么？
- 失败后谁在处理，改在哪个版本，回归是否通过？
- 客户拿到的报告，能否对应到上述全部证据？

### 目标用户

| 角色 | 主要诉求 |
| --- | --- |
| 电子 / 电力电子硬件工程师 | 版本变更、测试数据、缺陷整改闭环 |
| 嵌入式工程师 | 固件版本与功能 / 通信验证记录 |
| 测试负责人 | 计划编排、任务分派、审核、质量趋势 |
| 测试工程师 | 现场执行、测量录入、证据上传 |
| 项目经理 / 研发负责人 | 进度、风险、通过率、交付报告 |
| 高校实验室 | 轻量项目与用例管理 |
| 外部供应商 / 客户 | 只读查看项目与报告 |

### 产品原则

1. 一个项目统一管理；一个产品具有完整版本记录。
2. 每次执行必须绑定产品版本与测试条件。
3. 测试数据可追溯，阈值由用例配置而非代码写死。
4. 缺陷必须完整闭环，关闭必须有验证记录。
5. 多人协作使用统一业务数据与统一数据模型。
6. 多端按真实场景设计，不做 PC 页面等比缩小。
7. 重要数据修改保留审计历史。
8. 不把本地模拟包装成云端协同。

## 2. 业务对象与关系

```text
项目 Project
  ├── 需求 Requirement ──→ 测试用例 TestCase
  ├── 产品 Product
  │     ├── 硬件版本（PCB / BOM / 结构）
  │     ├── 固件版本
  │     ├── 软件版本
  │     └── 测试基线
  ├── 测试计划 TestPlan（绑定产品 + 硬件/固件版本 + 用例 + 人员 + 设备）
  │     └── 测试执行 Execution（RUN，绑定阈值、测量值、环境、设备、附件）
  │           └── 缺陷 Defect（失败 → 缺陷 → 修复版本 → 回归执行 → 验证 → 关闭）
  ├── 设备 Device（校准、使用、维修）
  ├── 数据集 Dataset（原始文件、波形、照片、BOM）
  └── 报告 Report（计划 / 单次 / 产品 / 版本对比 / 缺陷 / 验收）
```

## 4. 关键业务规则

### 4.1 版本与执行

- 每条执行必须关联 `项目 + 产品 + 硬件版本`，固件版本可选。
- 执行继承计划的用例、设备与测试人员，可在执行详情中调整环境参数。
- 测量值的上下限**来自用例步骤的参数配置**；业务代码不写死阈值。
- 判定规则：低于下限或高于上限 → FAIL；未录入 → PENDING；其余 → PASS。
- 存在任一 FAIL → 整条执行 FAIL；全部待录入 → PENDING。
- 提交执行时，必填测量项缺失会被拒绝。

### 4.2 缺陷闭环

```text
新建 → 待分派 → 处理中 → 已修复 → 待关闭 → 已关闭
                                  ↘ 重开
```

强制约束（服务层实现，非仅 UI）：

1. 提交“已修复”前必须填写根因分析与修复方案。
2. 只有“已修复”状态可以提交验证。
3. 验证必须关联**同一测试用例**且结果为 PASS 的回归执行。
4. 无验证记录不能关闭缺陷。
5. 关闭必须由具备 `review` 权限的角色执行。
6. 缺陷可一键创建回归计划（草稿→待执行）。

### 4.3 报告

- 报告章节与指标由计划 / 执行 / 缺陷 / 版本数据自动生成，不是空白模板。
- 审核人不能是作者本人。
- 只有审核通过的报告才能发布。
- 发布后可用于只读分享。

### 4.4 权限

- 菜单与操作入口按角色变化；访客只能看到被分享的项目与报告。
- 前端权限仅演示，真实授权由后端逐请求校验（见 NEXT_STEPS）。

## 5. 演示数据策略

- 组织：BenchFlow Demo Lab。
- 项目 4 个，产品 4 个，版本 13 个，用例 13 条，计划 6 个，执行 28 条，缺陷 6 个，设备 7 台，数据集 6 个，报告 6 份，模板 10 个。
- 所有日期以“当前时间”为锚点生成，保证趋势与“最近活动”始终合理。
- 关键闭环：
  - `RUN-0017`：TC-1002 满载纹波 65mV（限值 50mV）→ FAIL。
  - `BUG-0021`：由 RUN-0017 创建，整改版本 PCB V1.2 / FW V0.8。
  - `RUN-0019 / 0025 / 0028`：回归纹波 40–42mV，PASS。
  - `BUG-0021` 关闭，保留验证记录与回归执行。
  - `BUG-0020`：回归通过，状态“待关闭”；`BUG-0022`：处理中；`BUG-0023`：新建。
