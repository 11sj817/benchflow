### 2.3 2.1 关键流程与浏览器矩阵

**流程 A：项目 → 扫码 → 计划 → 用例 → 测量 → 照片 → 提交 → 移动执行详情**

1. PC 项目列表打开 P-2401，复制设备二维码内容；
2. 手机 `#/mobile/scan` 手动输入 `benchflow://device/DEV-001`；
3. 设备面板确认校准有效 →「用该设备测试」；
4. 记录页自动带入项目/产品/版本/计划/用例/设备；
5. 第二步录入 4 个测量项，拍照 1 张；
6. 第三步确认 → 提交；
7. 跳转 `#/mobile/executions/:id`，底部导航仍为任务 Tab。

结果：通过。步骤由 2.0 的约 7 步降为 3 步；页面未跳回 PC。

**流程 B：FAIL → 缺陷 → 分派 → 修复 → 回归 → 验证 → 关闭**

沿用 2.0 服务层约束；本轮验证移动执行详情「创建缺陷」自动带入 `executionId/projectId/productId/caseId`，以及缺陷详情在手机内完成分派、提交修复、验证、关闭、重开。通过。

**流程 C：项目 → 需求 → 计划 → 用例 → 分派 → 执行 → 报告**

沿用 2.0 闭环；本轮确认计划列表/需求列表的卡片视图、筛选记忆与快捷创建（`?create=1`）不会破坏原流程。通过。

**流程 D：同一浏览器移动端记录在 PC 可见**

手机提交 `RUN-00xx` 后，PC 执行列表刷新可见同一记录（LocalStorage + `storage` 事件）；另一浏览器不可见，符合本地演示边界。通过。

## 4. 缺陷与风险

| 编号 | 级别 | 描述 | 处理 |
| --- | --- | --- | --- |
| R-01 | 中 | Element Plus 全量引入导致首屏 chunk 偏大 | 记录为已知取舍；后续按需引入 / 拆 vendor |
| R-02 | 中 | LocalStorage 约 5MB，无法承载大型波形 | 界面明确提示；后端接对象存储 |
| R-03 | 低 | Excel 导出为 HTML `.xls`，样式与多 Sheet 受限 | 文档说明；后续接 SheetJS 或服务端导出 |
| R-04 | 低 | 浏览器打印生成 PDF 的页眉页脚依赖用户设置 | 报告页提供打印说明 |
| R-05 | 中 | 前端角色模拟可被绕过 | 明确非安全边界；后端必须重新校验 |
| R-06 | 低 | 跨标签页同步依赖 BroadcastChannel/storage | 不支持时刷新即可；不宣称云端协同 |

无阻塞级缺陷。

## 5. 结论

- 前端工程可构建、可测试、可静态部署。
- 18 个模块、核心三页（项目详情 / 用例编辑器 / 执行详情）与多端界面均已实现真实交互。
- 演示数据关联一致，缺陷闭环与报告审核约束由服务层强制。
- 当前不具备真实多用户与后端能力，相关限制已在界面与文档中明确标注。
